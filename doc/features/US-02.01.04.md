# US 02.01.04 — View my campsite details

Branch: `US-02.01.04`, based on `US-01.01.05`. Merge after entrant details.

Owner campsite cards open an owner detail route with the selected document ID. The shared detail view shows full stored information and updates from live snapshots. Both the list selection and the route restrict records to the active owner ID; missing identities cannot match legacy blank-owner records. Removal or changed ownership invalidates the open detail view. Back returns to the owner's list.

## Integration with Fahad and section E

The entry point supplies `Settings.Secure.ANDROID_ID` to `AppNavHost(ownerId = ...)`, consistent with the existing `User.deviceId` identity model. Once section E's identity feature is connected, it should supply the active `User.deviceId` at that same boundary. Newly registered records receive that owner ID in the existing registration callback. This is the minimum wiring needed to make ownership-based details reachable; registration form changes and admin functionality remain with Fahad.

Legacy documents whose `ownerId` is blank are not claimed automatically. Assign their correct owner ID in the shared database before expecting them in an owner's list. No shared Firebase data or access rules were changed. Owner selection here is client-side; the shared Firebase project's rules govern database access.
